# The human-edited source for requirements.lock, which is what CI and the
# Dockerfile actually install. Nothing installs THIS file directly.
#
# Editing a version here changes nothing until the lock is regenerated:
#   uv pip compile requirements.txt -c constraints.txt --generate-hashes \
#     --python-version 3.12 -o requirements.lock
#
# pip verifies a hash only when every requirement in the install carries one --
# it enters --require-hashes mode globally on seeing the first hash and then
# rejects any unhashed line, transitive dependencies included. That is why the
# lock is generated wholesale rather than a hash being pinned onto one package
# at a time, and why a hand-added line here is a no-op rather than a partial
# improvement.
